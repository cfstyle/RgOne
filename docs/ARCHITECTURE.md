# 行内大模型自助接入与案例门户 (RgOne Portal) 架构设计方案

## 一、 系统定位与目标
本系统旨在为银行纯内网离线环境下的员工提供零门槛接入自建 `DeepSeek Harness` 客户端与 `new-api` 算力网关的统一门户平台，解决以下关键痛点：
1. **纯 API 模式下的细颗粒度用量分析**：在不直连 `new-api` 数据库的前提下，利用轻量增量缓存与本地 SQLite 毫秒级输出多维用量报表。
2. **极简身份核验与防冒领**：员工免密仅凭工号即可发起查验，通过脱敏核对与全名双向精准匹配签发专属 Key，内置连续输错限流锁。
3. **100% 离线脱机运行**：严禁外网 CDN、Google Fonts 或外部图标库，所有依赖完全本地化。
4. **客户端双轨无缝引导**：界面五项参数一键复制与动态 `cordis.patch.yml` 补丁生成。

## 三、 数据库表设计规范 (SQLite + WAL)

| 表名 | 作用说明 | 关键约束与设计 |
| :--- | :--- | :--- |
| `employees` | 员工白名单底表 | `emp_no` 唯一索引；存储工号、真实姓名、部门及启用状态。 |
| `user_tokens` | 员工与网关 Token 映射 | `emp_no` 外键级联；`api_key_encrypted` 采用 Fernet 对称加密，防库文件泄露。 |
| `usage_logs_cache` | 消费日志本地增量缓存 | `new_api_log_id` 唯一索引实现幂等去重；复合索引 `(emp_no, created_at)` 支持秒级聚合。 |
| `shared_files` | 资料与安装包管理 | 存储安全文件名与原始名映射，记录 SHA256 与下载计数，支持“首页主推”标记。 |
| `articles` | 案例实践文章库 | Markdown 存储，支持分类、标签 JSON 数组、置顶与发布状态。 |
| `system_settings` | 全局动态键值对 | 运行时可热修改网关地址、Service Token（加密）、默认模型等配置。 |
| `admin_users` | 后台管理账号表 | `password_hash` 采用 bcrypt 强哈希算法。 |
| `auth_lockouts` | 防暴力枚举锁定表 | 记录连续错误次数与 `locked_until`，5次错误自动锁定10分钟。 |
| `verification_codes` | 动态验证码多进程共享表 | 记录 `emp_no, code_hash, expire_at, sent_at, is_used`，多 worker 共享，防并发原子消费。 |

## 四、 身份认证与统一登录架构

系统以银行内网生产安全与稳健接入为第一优先级，统一员工认证入口，并实现会话建立与算力网关凭据申领的彻底解耦：

### 1. 员工门户唯一生产登录路径：「工号 + 小秘书 6 位动态验证码」
- **进入方式**：员工端顶栏统一「工号登录」模态框。
- **解耦式会话建立**：
  - 员工输入行内 8 位工号（如 `06700956`、`06701099`）后点击「获取验证码」，发码成功后工号自动锁定且光标聚焦至验证码框。
  - 动态验证码校验成功后，系统立即签发员工专属 JWT 会话（`role: employee`，有效期 7 天），并留在原业务位置，无需强制页面跳转。
  - **登录与 Key 申领解耦**：首次登录成功后系统在后台自动向算力网关申领专属 API Key；已有 Key 自动复用。若因网关暂时故障或网络抖动导致申领失败，系统不阻断员工登录流程，员工进入系统后提示「已登录，Key 暂未申领成功」，并在当前会话内提供「重新申领」（`POST /api/v1/me/token/claim`）入口。员工重试时沿用当前会话，无需重新接收和输入动态码。
- **动态码与推送安全**：
  - 动态验证码使用标准库 `secrets` 安全生成（6 位数字），绝不在 API 响应、前端页面或服务日志中回传或打印。
  - 接收人定向绑定：生产环境中消息仅推送至当前登录工号名下对应的小秘书账号（`touser = emp_no`），员工输入他人普通工号无法窃取验证码；仅在显式配置 `XIAOMISHU_TEST_MODE=true` 时允许固定测试接收人。
  - 推送机制：仅在小秘书网关返回 HTTP 200 且业务确认推送成功后，验证码才允许入库生效；任何超时、网络中断或推送失败均返回明确错误，阻止落库可用验证码。
  - 多进程共享与原子消费：各 uvicorn worker 共享 SQLite `verification_codes` 表，落库加盐摘要 `SHA-256(APP_SECRET_KEY + emp_no + code)`。校验时采用原子条件更新（`UPDATE ... SET is_used = 1 WHERE emp_no = ? AND is_used = 0 AND expire_at > ?`），彻底杜绝并发重放。
  - 频率与锁定：60 秒发送冷却，5 分钟有效；连续输错 5 次工号与 IP 同时锁定 10 分钟。

### 2. 彻底废弃历史核验接口（「工号 + 姓名」已关闭）
- **接口下线说明**：生产环境中，原历史接口 `POST /api/v1/auth/emp/verify` 已彻底下线关闭，统一返回 `HTTP 403 Forbidden`。
- **安全保障**：仅凭工号与姓名无法在任何入口签发会话凭据、读取或操作 API Key。
- **展示姓名场景**：员工真实姓名仅在小秘书验证码登录成功后，在顶栏或工作台作为当前身份展示（如“陈飞 · 06700956”），登录前不要求输入姓名。

### 3. 管理员登录路径：「管理员账号 + 密码」
- **进入方式**：统一登录弹窗输入 `admin` 账号自动切换为管理员密码模式，或直连 `POST /api/v1/auth/admin/login`。
- **安全保障**：管理员凭 bcrypt 哈希校验通过后签发管理员专属 JWT（`role: admin`，有效期 24 小时），与员工端接口物理隔离。

## 五、 `NewApiClient` 网关适配与严格状态机

1. **请求鉴权标准头**：
   - `Authorization: Bearer <NEW_API_ACCESS_TOKEN>`
   - `New-Api-User: <NEW_API_USER_ID>`
2. **HTTP 状态与业务结果双重核验**：
   - 禁用、删除、创建与日志拉取接口均严格检查 HTTP 状态码为 200，并解析 JSON 中的 `success` 与 `errcode` 字段。
   - 网关故障（HTTP 非 200 或业务失败）时立即抛出 `RuntimeError`，严格保证本地数据库状态不发生错误漂移。
3. **统一 Key 重置与容灾状态转换机**：
   - **原子并发互斥锁**：进入重置时首先通过原子 CAS 将 Token 状态置为 `resetting` 中间锁状态。若并发请求在此期间到达，由于状态已被锁定，直接返回 HTTP 409 Conflict，杜绝多线程或快速双击导致网关残留孤儿 Key。
   - 员工自主重置与管理员后台强制重置复用同一事务逻辑：
     - **正常路径**：向网关删除旧 Key $\rightarrow$ 向网关创建新 Key（保持原 `token_name` 确保用量延续） $\rightarrow$ 校验取得有效非掩码 Key $\rightarrow$ 本地加密落库并恢复 `active` 状态。
     - **旧 Key 删除失败**：立即停止签发，本地 Token 状态与 Key 保持不变，向调用方传递明确网关错误。
     - **新 Key 签发失败**：若旧 Key 已删而新 Key 创建失败，本地 Token 记录标记为 `pending_reset` 可恢复状态（`new_api_token_id = None`），避免孤儿 Key。
     - **安全重试恢复**：当管理员或员工再次发起重置时，自动检测到 `pending_reset` 状态，跳过删除旧 Key 环节，直接向网关重试签发新 Key，成功后恢复为 `active` 状态。
     - **管理员禁用阻断**：若管理员已将员工账号或 Token 停用，员工发起自助重置返回 HTTP 403 Forbidden 明确拒绝，禁止重新获得可用 Key。
4. **全功能 Mock 模式**：
   - 内置 `MOCK_NEW_API=true` 开关，在本地研发或断网离线环境下自动模拟模型清单、Key 签发与增量日志消费数据，极大加速自测与迭代效率。

## 六、 员工停用、复职与网关联动管理

1. **员工停用联动吊销**：
   - 管理员在后台停用员工账号（`is_active = False`）时，系统立即阻断该员工的登录、读取凭证和重置 Key 权限。
   - 联动调用算力网关禁用其已绑定的网关 Token；若网关此时连通异常，本地保留停用状态，将 Token 状态标记为 `gateway_disable_pending`（网关吊销待重试），并在后台列表中醒目标注，提供一键重试吊销端点（`POST /admin/employees/{id}/retry-disable-token`）。
2. **显式复职要求**：
   - 管理员显式操作复职员工后，系统自动联动通知网关恢复其 Token 状态。
   - **名册批量导入保护**：批量导入（Excel / CSV）全行名册时，仅更新员工基本资料（姓名、部门），严格保留已有记录的 `is_active` 状态，严禁通过常规导入自动恢复已被停用人员的账号。
3. **员工删除防孤儿**：
   - 删除员工记录前执行安全检查，联动在算力网关上彻底删除该员工绑定的 Token；若网关删除失败则事务回滚并中止操作，避免在网关端残留无法追溯的孤儿 Token。

## 七、 日志增量同步与多维用量聚合架构

1. **单机单例互斥锁**：
   - 全行日志增量拉取采用基于 SQLite `SystemSetting` 键值对的原子单例互斥锁机制，支持 120 秒超时接管。
   - 当多请求或后台定时同步并发到达时，未获取到锁的请求立即返回 `HTTP 409 Conflict`（“全行日志增量同步正在进行中，请勿重复触发”），防止击垮网关日志接口。
2. **轻量员工端刷新**：
   - 员工工作台仅提供本地用量统计刷新（`POST /me/usage/sync`），展示当前员工已缓存明细的最新聚合数据与最近同步成功时间，不发起全行级别的全量拉取。
3. **数据库级直接聚合**：
   - 趋势统计采用 SQLite 原生 `func.strftime` 与 `GROUP BY` 直接在数据库引擎内分桶求和，无需将全量消费日志载入 Python 内存，内存开销严格维持在 O(1)。

## 八、 安全基线与加密规范

1. **凭证落库安全**：
   - 员工 API Key 与 网关 Access Token 在写入 SQLite 之前必须经由 `Fernet(APP_SECRET_KEY)` 对称加密。
   - 即使数据库文件直接被拷贝，攻击者也无法还原员工 Key。
2. **展示默认掩码与兼容复制**：
   - 门户首页与工作台展示 API Key 时默认采用掩码格式（如 `sk-rgon...7673`），提供自主显隐切换。
   - 提供剪贴板一键复制功能，并在纯内网 HTTP 协议环境下提供降级容错机制。
3. **接口访问控制 (RBAC)**：
   - 员工端会话 JWT 有效期为 7 天（`role: employee`）。
   - 管理员后台会话 JWT 有效期为 24 小时（`role: admin`）。
   - 两者鉴权依赖严格物理隔离。停用员工凭有效 JWT 访问受保护接口时同样会被即时拒绝（401/403）。
